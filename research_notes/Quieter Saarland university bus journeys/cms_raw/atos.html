    Advanced Topics in Operating Systems

    This course explores current research and engineering challenges at the intersection of operating systems, storage, and distributed computing. It is structured in two parts.

    The first part consists of six lectures on selected topics, including systems benchmarking and performance evaluation, ad-hoc file systems, distributed locking, and caching strategies. Some of these sessions are held in an inverted-classroom format: students prepare the material in advance using provided readings and recordings, and class time is devoted to discussion, problem solving, and deeper analysis. This part concludes with a mid-term exam. Passing the mid-term exam is a prerequisite for admission to the second part of the course.

    The second part is strongly hands-on. Working in small teams, students apply modern machine learning methods to an existing ad-hoc file system: first to analyze its behavior and performance characteristics based on traces, metrics, and workload data, and subsequently to optimize it by developing and evaluating data-driven improvements, e.g., in caching, prefetching, or data placement. To support the development work, participants in the project phase receive a license for Claude Code, an agentic AI coding assistant, for the duration of the course. The project phase concludes with a presentation and a written report in which students document their approach, experimental setup, and results.

    By the end of the course, students will be able to design and conduct rigorous performance evaluations of systems software, understand the design space of ad-hoc file systems and distributed coordination mechanisms, and apply ML techniques to real-world systems optimization problems.

    The final grade will consist of the best score out of two midterm exams along with a final presentation. One of the midterm exams must be passed in order to qualify for part 2 of the lecture. The dates are as follows:

    Lecture 1 – Performance Evaluation (October 23, 2026)

    How to measure a system so that the numbers mean something. The first half covers choosing metrics, micro- vs. macro-benchmarks, standard suites, and Gernot Heiser’s catalogue of benchmarking crimes; the second half the profiling toolbox (perf, flame graphs, performance counters, eBPF), sources of measurement noise, and the statistics needed to tell a real effect from noise.

    The slide deck, as well as all following materials designed by us, is available under Information → Materials.

    Lecture 2 – Parallel File Systems I: PVFS (inverted classroom, October 30, 2026)

    The first inverted-classroom session discusses a basic parallel file system, PVFS, and its implementation choices: striping files across I/O nodes, a single metadata manager, a user-level design over TCP, and the deliberate absence of caching and locking. In class we examine what these choices buy, what they cost, and where they stop scaling, the questions later systems in this course answer differently.

    Preparation: read the paper P. Carns, W. Ligon, R. Ross, R. Thakur, PVFS: A Parallel File System for Linux Clusters, 4th Annual Linux Showcase & Conference, 2000 (https://www.usenix.org/conference/als-2000/pvfs-parallel-file-system-linux-clusters). Write a short, fixed-format reading response for yourself: the paper’s main claim in two sentences; the one design decision you found most surprising or questionable; one thing you didn’t understand; one question you’d want to ask the authors. Bring it to class, it is the basis for the discussion.

    Reading guide: after reading the paper, you should be able to compute which I/O node holds a given byte of a file; explain what PVFS gains and loses by having neither client caching nor locking; say when a single metadata manager stops being acceptable; explain what the strided access via offset, gsize and stride in Section 3.3 solves that plain POSIX reads and writes do not; and explain how the three APIs reach the client library and why a kernel module was added anyway.

    Optional background: the paper assumes you know what MPI and MPI-IO are. If you don’t, ten minutes each on the first two sections of the Wikipedia article on the Message Passing Interface (https://en.wikipedia.org/wiki/Message_Passing_Interface) and on the MPI-IO page of the Digital Research Alliance of Canada (https://docs.alliancecan.ca/wiki/MPI-IO), which explains file views with a short code example, is enough.

    Pre-class exercise: A file is created with ssize = 64 KiB, pcount = 8 and base = 2 on a cluster with 10 I/O nodes (0–9). (a) Which I/O node holds byte 1,000,000? (b) How many I/O nodes does a 1 MiB read at offset 3 MiB touch, and how many stripes does each serve?
